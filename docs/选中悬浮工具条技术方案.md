# 选中悬浮工具条技术方案（素材模块 + 浏览器模块）

> 借鉴 ima / Google Docs / Notion 的交互：**选中文字后，在选区上方浮出一个横向工具条**，取代原来的「右键弹菜单」，让高频动作一步可达。

---

## 0. 硬约束（最高优先级，任何阶段都不得违反）

**本次改造只涉及两个模块：素材模块、浏览器模块。其他模块一律不动。**

具体红线：

1. **不动文档模块**。`RichEditor.vue` 是「文档模式 / 素材模式」共用组件，本次只允许修改 `editMode === 'material'` 分支相关逻辑；`!editMode || editMode === 'document'` 的右键菜单模板（`RichEditor.vue:2778-2807`）、剪切/粘贴/批注/校对等文档专属逻辑**一行都不能改**。
2. **不动编辑器文档态右键**、不动 `EditorView.vue` 左右侧栏的 `onSidebarContextMenu`（`EditorView.vue:130-142` / `1674` / `2152`）——那属于侧栏，不属于本次的「素材内容区」。除非后续用户明确追加。
3. **不动 AI 对话、候选库、比对、批注、校对等下游功能的内部实现**。悬浮条只复用它们已有的入口函数/事件通道。
4. 回退策略统一为 **「有选区时右键回退到原生菜单」**（不再弹自定义 AiPen 菜单，也不 `preventDefault`）。

## 1. 现状分析（改造起点）

### 1.1 浏览器模块
- 注入脚本：`src-tauri/src/commands.rs` 的 `BROWSER_INIT_SCRIPT` 常量，函数 `__aipenSetupContextMenu`（`commands.rs:1940` 起）。

- 主题：`getTheme()` 已实现浅/深色自适应（`commands.rs:1949`）。

> 注意：浏览器模块此前**没有**「加入比对」菜单项（只有 素材库/对话/候选/复制）。
> **本次变更**：在浏览器工具条补齐「↔️ 加入比对」，与素材卡片工具条、文档右键菜单完全对齐——复用 `compareStore.addEntry`，不新增任何比对逻辑分支。设计与回归见第 6 节修复清单。

## 2. 目标设计

### 2.1 交互统一规范（两模块视觉/行为对齐，但各自实现）
- **出现时机**：选区从空 → 非空（`selectionchange` 稳定后，或 `mouseup` 时）出现。
- **定位**：选区外接矩形（`getBoundingClientRect`）**正上方居中**；上方空间不足则翻转到选区下方；靠视口边缘做水平夹取，不出界。
- **消失时机**：选区变空、点击工具条外部、滚动、窗口 resize、按 Esc。
- **不破坏选区**：工具条根元素 `mousedown` 执行 `preventDefault()`，避免点击时选区被清空。
- **右键行为**：有选区右键 → **不弹自定义菜单，回退原生**；无选区右键 → 维持现状。
- **视觉**：横向排列图标+文字的按钮，浅/深色自适应，圆角、轻投影、毛玻璃，风格与现有菜单一致。

### 2.2 两模块的工具条内容
| 模块 | 工具条按钮（从左到右） |
|---|---|
| 浏览器 | 复制 · 📦 存入素材库 · 💬 添加到 AI 对话 · 📋 添加到候选库 · ↔️ 加入比对 |
| 素材卡片 | 复制 · 💬 添加到 AI 对话 · 📋 添加到候选库 · ↔️ 加入比对 |

> 说明：浏览器现已与素材卡片、文档右键统一具备「加入比对」（复用 `compareStore.addEntry`）。"存入素材库"为浏览器独有，符合各自现状语义，不强行统一。

### 2.3 为什么不做通用组件
浏览器工具条运行在**外部网页的 webview 上下文**（注入的原生 JS 字符串），素材工具条运行在**主窗口 Vue 上下文**，二者 DOM/运行时完全隔离，无法共享组件实例。**策略：各自实现，交互与视觉规范对齐**（见 2.1）。

## 2.5 滚动锁定（ima 设计理念）

> **ima 交互哲学（仅适用于素材、浏览器模块，不改动文档模块）**：只要选区工具条出现，底层内容就**不允许滚动**——用户正聚焦于刚选中的文字与工具条动作，滚动会打断这一意图，并让浮层错位。工具条存在期间，屏蔽滚轮 / 触摸滚动 / 键盘滚动（方向键、PageUp/Down、空格）。

**适用对象（仅素材、浏览器模块；文档模块一律不改）**：

| 模块 | 滚动锁定点 | 实现位置 |
|---|---|---|
| 浏览器 | 工具条显示期间 | `commands.rs` 注入脚本：工具条挂载时对网页 `window.addEventListener('wheel'/'touchmove', preventDefault, {passive:false})`；关闭时移除监听 |
| 素材 | 选区工具条显示期间 | `RichEditor.vue` 的 `editMode === 'material'` 选区工具条：显示时拦截 `wheel`/`touchmove`（`preventDefault` 或 `overflow:hidden`），隐藏时恢复 |

**行为细则**：
- 仅屏蔽"内容滚动"，不屏蔽工具条 / 菜单自身的点击、悬停。
- 工具条消失的任一触发条件（选区变空、点外部、resize、Esc、点按钮）都必须**同步解除**滚动锁定，避免"锁死"无法恢复。
- 浏览器：运行在外部 webview，只能用 `addEventListener` 在网页上下文内拦截，无法用 Vue 指令；务必在 `cleanup()` 中**成对**移除监听。
- 素材：优先"滚动即隐藏"——工具条显示时（选区稳定）不滚动，选区一变 / 滚动即隐藏，故滚动锁定与"隐藏"可合并处理，实现最简。

### 阶段二（素材）实现细节 & 坑
- **改动范围**：仅 `src/components/RichEditor.vue`，全部逻辑用 `props.editMode === 'material'` 严格 gating；文档模式 `ctx-menu` 模板与 `contextmenu` 分支一行未改。
- **右键回退**：`handleDOMEvents.contextmenu` 首行加 `if (props.editMode === 'material') { hideMatToolbar(); return false }`，material 不再 `preventDefault`、不弹 ctx-menu → 回退系统原生菜单；文档模式保持 `event.preventDefault()` 原逻辑。
- **选区来源**：素材卡片以 `:readonly="true"` 渲染，用**浏览器原生选区** `window.getSelection()` 取文本与 `getRangeAt(0).getBoundingClientRect()` 取定位（而非 `ed.state.selection`，readonly 下更可靠）。
- **多卡片隔离**：`matSelInThisEditor()` 用 `editor.value.view.dom.contains(sel.anchorNode)` 判断选区是否落在**本**卡片编辑器内，避免多卡片实例互相误弹。
- **按钮复用**：工具条 4 个按钮 `matCopy/matChat/matCandidate/matCompare` 直接调用现有 `execCtxMenuCopy / execCtxMenuInsertToChat / execCtxMenuAddToCandidate / execCtxMenuAddToCompare`（先把 `ctxMenuSelText.value` 设为当前选中文本供其复用），未改这些函数内部实现。
- **不抢选区**：工具条根元素 `@mousedown.prevent`；document 级 `mousedown`/`mouseup` 捕获监听遇到工具条内部 target 时提前 return。
- **滚动即隐藏**（§2.5 素材策略）：`scroll`(capture)/`resize` → `hideMatToolbar()`，不做滚动锁定，最简稳妥；另 `selectionchange`(120ms 防抖)/`mouseup`/`Esc`/右键 均触发隐藏或重定位。
- **防闪烁**：先以 `visibility:hidden` 挂载测量真实宽高，`nextTick` 后夹取/翻转定位再置 `visible`（`matTbPositioned`）。
- **定位**：选区外接矩形正上方居中，上方不足翻转到下方，左右夹取不出界（与浏览器工具条一致）。
- **视觉**：`.mat-float-toolbar` 复用与浏览器工具条同款 ima 风格（毛玻璃胶囊 + 深阴影 + 线性 SVG 图标 + 13px/500 文字），浅/深色由 `.is-dark` 切换。

## 5. 风险与预判坑位

| 风险点 | 说明 | 预案 |
|---|---|---|
| 误伤文档模式 | RichEditor 共用，改错分支会破坏文档右键 | 所有新增逻辑用 `editMode === 'material'` 严格 gating；改完做文档模式回归 |
| `selectionchange` 高频 | 每次选区变动触发，可能卡顿 | 防抖（如 120ms）+ 空选区早退 |
| 工具条抢选区 | 点击按钮导致 selection 清空、text 变空 | 根元素 `mousedown` `preventDefault`；点击瞬间用已缓存的 text |
| 选区定位不准 | 折行/跨段选区 rect 复杂 | 用 `getRangeAt(0).getBoundingClientRect()`，退化时用 `getClientRects()[0]` |
| 原生菜单是否可用 | 回退原生依赖 webview 未全局禁用右键 | 浏览器侧当前"无选区右键"已能出原生菜单，说明可用；素材侧在主窗口，原生菜单默认可用 |
| 输入框内选区 | 网页/卡片中的 input/textarea 选区 | 判断 `activeElement` 类型，必要时早退 |
| 滚动错位 | 卡片列表/页面滚动后工具条位置失效 | 滚动即隐藏（首选）或重新计算 rect |

## 6. 候选库 / 比对面板在素材·浏览器模块的可见性修复清单（最后修复）

> **背景**：用户反馈——在「素材 / 浏览器」模块使用「加入候选库 / 加入比对」后，**左侧候选库抽拉图标没有出现（被遮掩）**，比对面板也疑似同类问题。
>
> **根因（已定位）**：
> 1. `CandidatePanel` 当前挂在 `RichEditor` 的 `#overlay` 插槽内，而该插槽位于 `RichEditor.vue:2642` 的 `<div class="flex flex-1 min-h-0 relative overflow-hidden">` 之中 → `overflow-hidden` 把触发图标 `translateX(-57%)` 探出的部分裁掉（即"被遮掩"）。
> 2. 浏览器模式（`editMode === 'webview'`）下 `RichEditor` 整体不渲染（`EditorView.vue:2088` 的 `v-else-if="editMode !== 'webview'"`）→ `CandidatePanel` 根本不挂载 → 图标不出现。
> 3. 比对面板在右侧 `CommentListPanel` 抽屉，若右侧栏被折叠，则「加入比对」后看不到。
>
> **修复原则（硬约束）**：**严格沿用候选库、比对面板在「文档模块」的既有实现逻辑，不改动既有设计**。
> - 候选库：`candidateStore.add(...)` + `CandidatePanel` 抽拉面板（设计稿见 `global-search-candidate-plan.md` §4.4，本就要求挂在 `<main>` 内、`position:absolute`、`z-index:100`）。
> - 比对：`compareStore.addEntry(text, label)` + 右侧 `CommentListPanel` 双 tab 抽屉（设计稿见 `compare-panel-spec.md`）。
> - 素材 / 浏览器模块**只负责触发（调用 store）和保证面板可见**，不得另写一套候选/比对 UI 或逻辑分支。
