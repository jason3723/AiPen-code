## v4.2.7 (2026-07-14)

### 🐛 修复

- **短文本校对报 `expected , or }` 解析失败**：根因为模型在 `reason` 字段用未转义的英文半角引号 `"` 包裹错误词（如 `"甘"与"干"`），直接把 JSON 切断。已在 prompt 中加入硬约束：`reason`/`suggestion`/`original` 字段值严禁出现英文双引号，标注错误词一律用 `×` 包裹（如 `×甘×`），`reason` 必须单行；从源头消除非法 JSON。
- **波浪线画到错误位置（如"在见"标出却画在"顺遍在那"上）**：原逻辑部分信任 AI 返回的 `start`/`end` 偏移，当 AI 把"哪几个字错了"与"改成啥"字段错配时，因 `original` 恰好能在原文找到而自洽通过，画出错位波浪线。改为**始终以 `original` 为唯一锚点**在原文中确定性搜索定位，字段错配（`original` 非原文子串）的条目直接丢弃，绝不用错误偏移画波浪线。
- **重复标点波浪线塌缩到首个位置**：原 `char_find` 只返回第一个匹配，当 `original` 为单个重复字符（多个半角逗号 `,`、多个句号 `。` 等）时，所有同类条目都被定位到最前面一处。新增 `char_find_nearest`：优先选择「离 AI 给出的 `start` 最近、且不与已放置区间重叠」的那一处，使每条重复标点落到各自实际位置。

### 🔧 优化

- **解析失败不再伪装"无错"**：校对响应 JSON 解析失败时明确报错（提示"请缩小选区后重试"），不再静默返回空结果骗用户"无问题"。
- **标点召回强化**：执行流程新增"逐字符扫描全文半角 ASCII 标点（`, ; : . ? ! ( )` 等），凡在汉字之间、应作全角处一律标出"的硬性步骤，降低模型在错别字密集时漏标半角标点的概率。
- **抑制正确标点的误报波浪线**：后端新增硬兜底——`suggestion` 与 `original` 字面相同（无实际修改）的条目直接丢弃；同时在 prompt 中明确"仅当原文确实用了半角符号才标出，标点已是正确全角时不输出该项"，杜绝模型对正确全角标点强行输出"此处已全角，无错"类无意义波浪线。

## v4.2.3 (2026-07-12)

### ✨ 新增

- **实时校对（Proofread）功能**：手动触发、只标不改，需用户确认后才替换，避免误改正文。
  - **后端 `proofread` 命令**（`ai.rs`）：将纯文本交给全局 AI 模型做零样本校对，返回 `{category, original, suggestion, reason}` 列表，以字符偏移定位；解析做了容错（剥离 ```json 围栏、截取首个 `[...]`、失败降级为空），不卡死流程。
  - **编辑器内红色波浪线标注**（`RichEditor.vue` 的 `proofreadPlugin`）：对疑似问题文本画波浪线，hover 浮层显示「建议」与「原因」；编辑命中问题区间自动移除标注，其余项随改动实时重映射。
  - **工具栏「校对」图标**：无选区校对全文、有选区只校对选区；校对进行中 / 面板打开时按钮高亮。
  - **校对面板集成进统一抽屉**（`CommentListPanel.vue`）：每条结果支持「📍跳转 / ✎替换 / ✓标记为正词 / 忽略」；切换文档自动清空结果（正词为全局设置，保留）。
  - **正词管理器**（全局、`localStorage` 持久化 `aipen_proofread_correct_words`）：添加后实时抑制命中该词的误报，支持增 / 删 / 改。
  - **偏移量 ↔ 文档位置映射工具**（`src/utils/docOffset.ts`）：序列化与定位共用同一套分隔规则（块级之间单 `\n`），字符级计数与 Rust 端 `text.chars().count()` 一致，保证波浪线精确落到正确位置（中文不错位）。

### 📝 变更

- 删除旧实验性规则引擎文档 `docs/PROOFREAD_RULE_ENGINE.md`：校对结果改为直接由 AI 零样本生成，不再依赖本地规则库。

### 🐛 修复

- **修复全屏/沉浸模式下左右面板折叠后无法复原**：浏览器是 OS 级 WebView2 窗口，DOM 的 `z-index` 无法压在其之上。原视口左右铺满中央区域，折叠按钮挪到窗口边缘后被浏览器盖住。`getBrowserViewportRect()` 在左右各预留 24px 的 `gutter`，按钮始终落在浏览器范围之外、可见且可点。
- **修复打开网页后，教程/反馈/排版设置弹窗被网页遮住看不到**：这些弹窗虽为 `Teleport` 到 body 的高 `z-index` DOM，但仍被 OS 级浏览器窗口盖住。现新增 `browserOverlayOpen` 监听，弹窗（教程/反馈/排版设置/关于）打开时 `hide_browser()` 临时隐藏浏览器，关闭后按当前 `leftSubTab` 状态重定位并 `show_browser()`（网页状态保留不销毁）。
- **修复右键面板「刷新」后网页残留顶端、不随刷新销毁**：原 `handleReload` 直接 `location.reload()` 只重载主窗口前端，Rust 创建的独立 WebView2 窗口未被销毁，变成孤儿窗口残留顶层。现先 `close_browser()` 显式销毁再重载，残留消失。
- **修复左右面板折叠/展开后浏览器视口不跟随、两端留白或面板被网页盖住**：原 `repositionBrowser` 仅监听 window `resize`/`focus`/`scale`，面板 200ms 折叠过渡期间不触发。现新增 `ResizeObserver` 直接观察中央区域 `mainAreaRef`，面板展开/折叠全过程同步重定位浏览器；卸载时 `disconnect()` 清理。

## v4.2.2 (2026-07-10)

### 🐛 修复

- **修复新版本使用手册（教程文档）打开后内容空白的问题**：4.2.1 引入的新版 `src-tauri/resources/tutorial.md` 包含大量无序/有序列表，但编辑器 schema 未注册列表节点，导致 `setContent` 抛出 `Node type "bulletList" not found` 并被 `try/catch` 重置为空文档（只剩标题）。已恢复编辑器对 `bulletList`/`orderedList`/`listItem` 节点的支持，教程与含列表的用户文档均可正常渲染。
- **修复内置浏览器窗口在最大化/全屏后不跟随放大、四周留白的问题**：最大化与沉浸模式切换时，窗口 `resize` 事件在 `isResizing` 标记期间被 `onBrowserResize` 拦截，且结束后无 trailing 事件，导致浏览器 WebView 停留在旧尺寸。`handleMaximize` / `handleToggleFullscreen` 收尾时主动重定位浏览器；并新增 `onScaleChanged` 监听，在 DPI / 显示缩放变化（如拖到不同缩放比显示器）时也重定位，消除对齐死角。
- **修复经地址栏/素材面板打开浏览器后，切换到文档/素材面板时网页仍置顶不消失的问题**：原打开路径只调用 `show_browser` 弹出覆盖层，未将 `leftSubTab` 同步为 `'browser'`，导致切到文档/素材时 `leftSubTab` 未变化、隐藏浏览器的 `watch` 不触发。`handleOpenBrowser` 现同步 `leftSubTab = 'browser'`，使地址栏/素材面板打开与"浏览器"标签页打开状态一致，切面板即可正确隐藏浏览器（并顺带让"切换即保"对地址栏打开的浏览器也生效）。
- **修复右键菜单粘贴单段文字时头尾自动换行的问题**：右键"粘贴"走 `execCtxMenuPaste`，经 `textToDocJson` 把每行包成独立 `paragraph` 块后整体 `insertContent`，插入光标所在段落中间时被切开，导致头尾各断一行。现对单段落纯文本只插入其内联内容（不插 `paragraph` 块），光标停在文末、不再换行；多段落/标题/列表仍按块级插入（本就该分段）。该路径不含 `\n`、不产生 `hardBreak` 内联节点，因此不会重现此前已修复的"光标跳脱"位移。仅影响右键菜单粘贴，Ctrl+V 原生粘贴路径不受影响。

### 📝 变更

- 列表节点仅在 schema 层注册用于渲染，**关闭其输入规则**（敲 `- `/`1. ` 不再自动转为列表），且工具栏不显示列表按钮，保持编辑体验简洁。

## v2.0.6 (2026-07-04)

> 本次更新聚焦于**编辑器交互体验**:工具栏重排、深色模式质感升级、防白闪优化。

### ✨ 优化与改进

#### 编辑器工具栏重排
- **大纲导航置顶**:大纲按钮移至工具栏最左侧,作为首要导航入口
- **按功能属性分组**:将原 14+ 个按钮按"导航 / 编辑历史 / 基础文字格式 / 高级文字样式 / 段落样式 / 段落排列 / 列表 / 插入元素 / 文档工具 / 字体字号"分组,组间用分隔符清晰分割

- 整体布局参考主流文字处理器,**符合用户认知习惯**

#### 深色模式质感全面升级
解决此前深色模式"发闷、不通透、字体发暗"的问题,采用**三层深度体系**重构配色:

| 层级 | 区域 | 旧色 | 新色 |
|------|------|------|------|
| 最深(暗) | 工具栏 | `#1e1e2e` | `#14151d` |
| 中间 | 下拉面板 | `#252540` | `#1a1c29` |

- **激活态精致化**:`#60a5fa` → `#89b4fa`,更现代通透

- **元信息可见度提升**:`rgba(255,255,255,0.04)` → `0.06`
- 占位符、引用块、代码块、搜索高亮、上下文危险悬停等 11 项 CSS 变量同步调整
- 浅色模式保持不变,无回归

#### 防白闪三道防线
解决 Tauri 应用启动 / 窗口切换时的**白屏闪烁**问题,深浅模式通用。

| 防线 | 防御对象 | 实现 |
|------|----------|------|
| **第一道** | OS 窗口 client area 默认白 | `tauri.conf.json` `backgroundColor: #2a2c3c`(中性色) |
| **第二道** | 浏览器 body 默认白(CSS 加载竞速) | `index.html` 内联 CSS 变量,首帧即正确主题色 |
| **第三道** | 主题 class 注入延迟(JS 加载竞速) | 同步 IIFE 提前打 `.dark`,纳秒级 |

- **中性色 `#2a2c3c`** 介于浅色和深色之间,深色用户从 ΔL=88 的"白→深"突变降为 ΔL=30 的"中性→深",感知不到
- 浅色用户从"白→白"无感,不会被反向突兀

#### 主题系统重构(user/system 双模式)
- 新增 `source` 字段,区分"用户显式选择"与"跟随系统主题"
- 首次启动默认**跟随系统主题**(`prefers-color-scheme`)
- 系统主题切换时自动跟随(仅在 source=system 时响应)
- 用户手动切换后 source=user,持久化到 localStorage
- 切回"跟随系统"会清掉显式选择记录,避免污染
- `useTheme()` API **完全向后兼容**,新增 `followSystem()` 方法

### 🐛 修复

- 浅色 / 深色模式切换时偶发的"白闪"问题(三道防线彻底根除)
- 启动后首帧文字颜色短暂为深色的问题(同步 IIFE 在 CSS 应用前完成 class 标记)

### 📝 兼容性说明

- v2.0.5 及更早版本的 `localStorage` 中只有 `aipen-theme` 键,无 `aipen-theme-source` 键
- 老用户首次启动 v2.0.6 时,会被识别为"无 source 记录",**默认转为跟随系统**

## v2.0.5 (2026-07-04)

### 🏗️ 架构升级

#### 存储格式全面切换为 ProseMirror JSON
- **编辑器引擎**:从 Milkdown(Markdown)迁移至 **TipTap (ProseMirror)**,实现所见即所得的富文本编辑
- **存储格式**:文档内容以 ProseMirror JSON 格式存储(`{type:"doc", content:[...]}`),保留完整排版语义
