# 文档批注功能 · 技术方案

> AiPen 桌面端（Vue 3 + TipTap/ProseMirror + Pinia + Tauri/Rust + SQLite）
> 范围：单用户、单机、无协作、无登录。
> 目标：选中文字 → 插入批注 → 下划虚线 + 角标 + 文末列表 → hover 弹内容 → 草稿/版本/回滚自动同步 → 备份可勾选导出导入。

---

## 1. 需求与设计目标

### 1.1 核心需求

1. 选中文字 → 工具栏 / 右键菜单「**插入批注**」→ 选中段加下划虚线 + 出现上角 `[n]` 引用（自动按序）
2. 鼠标悬停下划虚线文字 → 自动弹出批注内容
3. 批注文字保存逻辑与正文一致：
   - 不删 → 提交版本时与正文一起保存
   - 删除 → 不影响历史版本（历史版本永远只反映提交那一刻的快照）
4. 备份导出/导入支持，在 **API 设置面板的备份模块** 可被勾选

### 1.2 设计目标

- **零侵入存储**：批注不存到独立表，而是作为 ProseMirror 文档 JSON 的一部分存到 `documents.content` / `versions.content`
- **整树快照自动同步**：草稿、版本、回滚、切换文档、备份导入导出全部「白送」
- **单段内选区**：v1 限制为「同一段连续选区」，跨段 UI 引导、schema 自然约束
- **孤儿批注保留**：删掉带批注的整段，批注保留为「孤儿」，文末标灰仍可查看
- **导出 Word 简化方案**：角标 + 文末列表（不实现 Word 原生批注 API）

### 1.3 明确不做

- 多用户协作（@、回复、已解决、权限）
- Word 原生「修订」模式（接受/拒绝 + 双色标记）
- Word 原生批注 XML
- 跨段选区批注
- AI 自动批注（可在 v2 把批注作为 Skill 输出落点）

## 3. 数据模型

### 3.1 ProseMirror 文档 JSON 顶层扩展

在 doc 节点同级新增一个 `comments` 字段（**非节点内容，是文档元数据**）：

```ts
// src/types/comment.ts
export interface Comment {
  /** 全局唯一 ID，UUID v4 */
  id: string;
  /** 顺序号，从 1 自增，删除也不回收（保持 [n] 编号稳定） */
  order: number;
  /** 批注文字，<= 500 字 */
  text: string;
  /** 创建时间，ISO 8601 */
  createdAt: string;
  /** 最近修改时间，ISO 8601 */
  updatedAt: string;
  /** 关联作者（单用户场景下固定为「我」，保留扩展位） */
  author: string;
  /** 关联的 ProseMirror Mark 范围（动态计算，不存） */
  // anchor: { from: number; to: number };
  /** 孤儿标记：true 表示原文已被删除，仅在文末列表保留 */
  orphan: boolean;
}

export interface CommentMarkAttrs {
  commentId: string;
}
```

### 3.2 ProseMirror doc 节点 spec 调整

```ts
// 当前：{ type: "doc", content: [...] }
// 扩展：{ type: "doc", content: [...], comments: Comment[] }
```

> ProseMirror 允许 doc 节点携带任意 `attrs`，但项目当前实现走 `JSON.parse(content)` 直接喂给 EditorView，需要在 `parseContent` 末尾把 `comments` 字段「剥离」到 store，序列化时再写回。

### 3.3 Comment Mark spec

```ts
// src/components/RichEditor/extensions/comment.ts
const CommentMark = Mark.create({
  name: "comment",
  inclusive: false,        // 不跨光标位置延伸
  excludes: "",            // 允许与 highlight/bold 等共存
  spanning: true,          // 允许跨多个 inline 节点

  addAttributes() {
    return {
      commentId: {
        default: null,
        parseFromHTML: () => null,
        renderHTML: () => ({}),   // 不渲染到 HTML（避免复制粘贴泄漏）
      },
    };
  },

  parseHTML() {
    return [{ tag: "span[data-comment-id]" }];
  },

  renderHTML({ HTMLAttributes }) {
    return [
      "span",
      {
        ...HTMLAttributes,
        "data-comment-id": HTMLAttributes.commentId,
        class: "comment-mark",
      },
      0,
    ];
  },

  addCommands() {
    return {
      setComment: (commentId: string) => ({ commands }) =>
        commands.setMark("comment", { commentId }),
      unsetComment: () => ({ commands }) => commands.unsetMark("comment"),
    };
  },
});
```

### 3.4 角标 `[n]` 的渲染策略

**不**用 inline sup 节点（会污染文档 JSON），改用 **ProseMirror Decoration** 渲染视图层装饰：

```ts
// src/components/RichEditor/decorations/commentBadge.ts
export function buildCommentDecorations(view: EditorView, comments: Comment[]): Decoration[] {
  const decos: Decoration[] = [];
  const sorted = comments.filter(c => !c.orphan).sort((a, b) => a.order - b.order);

  view.state.doc.descendants((node, pos) => {
    const mark = node.marks.find(m => m.type.name === "comment");
    if (!mark) return;
    const comment = sorted.find(c => c.id === mark.attrs.commentId);
    if (!comment) return;

    // 角标：放在该 mark 范围末尾
    decos.push(
      Decoration.widget(pos + node.nodeSize, () => {
        const el = document.createElement("sup");
        el.className = "comment-badge";
        el.textContent = `[${comment.order}]`;
        el.dataset.commentId = comment.id;
        return el;
      }, { side: 1, key: `comment-badge-${comment.id}` })
    );
  });

  return decos;
}
```

## 4. 状态管理

### 4.1 store 扩展

在 `src/stores/document.ts` 中新增：

```ts
// ── 批注状态 ──
const comments = ref<Comment[]>([]);
const hoveredCommentId = ref<string>("");
const editingCommentId = ref<string>("");
const orphanCleanupEnabled = ref<boolean>(false);  // 是否允许清理孤儿

// ── 计算属性 ──
const commentById = computed(() => {
  const m = new Map<string, Comment>();
  for (const c of comments.value) m.set(c.id, c);
  return m;
});

const nextCommentOrder = computed(() => {
  if (comments.value.length === 0) return 1;
  return Math.max(...comments.value.map(c => c.order)) + 1;
});

// ── 操作 ──
function addComment(text: string, anchor: { from: number; to: number }): Comment {
  const c: Comment = {
    id: crypto.randomUUID(),
    order: nextCommentOrder.value,
    text,
    createdAt: new Date().toISOString(),
    updatedAt: new Date().toISOString(),
    author: "我",
    orphan: false,
  };
  comments.value = [...comments.value, c];
  // 通过 ProseMirror command 加 mark
  applyCommentMark(c.id, anchor);
  scheduleDraftSave();
  return c;
}

function updateCommentText(id: string, text: string) {
  const idx = comments.value.findIndex(c => c.id === id);
  if (idx === -1) return;
  comments.value = comments.value.map(c =>
    c.id === id ? { ...c, text, updatedAt: new Date().toISOString() } : c
  );
  scheduleDraftSave();
}

function deleteComment(id: string) {
  // 1. 移除 mark
  removeCommentMark(id);
  // 2. 从数组删除
  comments.value = comments.value.filter(c => c.id !== id);
  scheduleDraftSave();
}

/** 当 mark 范围在文档中消失（如整段删除），把对应 comment 标为 orphan */
function sweepOrphans() {
  const liveIds = new Set<string>();
  // 遍历 doc 收集所有 comment mark 的 id
  collectLiveCommentIds(liveIds);
  let changed = false;
  comments.value = comments.value.map(c => {
    if (!c.orphan && !liveIds.has(c.id)) {
      changed = true;
      return { ...c, orphan: true };
    }
    return c;
  });
  if (changed) scheduleDraftSave();
}
```

### 4.2 serializeContent / parseContent 兼容

```ts
// 现有：parseContent 把 JSON 字符串 → ProseMirror doc
// 改为：

export function parseContent(json: string): { doc: PMNode; comments: Comment[] } {
  const raw = JSON.parse(json);
  const { comments = [], ...rest } = raw;
  // 兼容老文档：comments 字段缺失时不报错
  return {
    doc: { type: "doc", content: rest.content ?? [] } as unknown as PMNode,
    comments: comments as Comment[],
  };
}

export function serializeContent(doc: PMNode, comments: Comment[]): string {
  const obj = doc.toJSON();
  return JSON.stringify({ ...obj, comments });
}
```

> 兼容点：v1 文档没有 `comments` 字段 → `parseContent` 解析时 `comments = []`，不报错。`serializeContent` 写出的 v1 文档能被老版本（理论上不会存在）忽略多余字段。

### 4.3 切换文档 / 加载版本 / 回滚

现有 `loadVersionContent` / `rollbackToVersion` / `exitHistoryView` / `switchDocument` 全部走 `parseContent` / `serializeContent`，**只需在调入口把 `comments` 字段塞进/读出 store**，其他逻辑白送：

```ts
// 示例：loadVersionContent
async function loadVersionContent(versionId: string) {
  await withSuppressDraftSave(async () => {
    const version = await invoke<Version>("get_version", { versionId });
    if (version.doc_id !== currentDocId.value) return;
    const { doc, comments: cmts } = parseContent(version.content);
    currentContent.value = doc;
    comments.value = cmts;        // ← 新增
    viewingVersionId.value = versionId;
    loadDocumentScore();
  });
}
```

## 6. 撤销/重做与事务

TipTap/ProseMirror 的 Mark 操作**天然支持 undo/redo**，但要注意：

```ts
// 工具栏 / 右键触发的"插入批注"应作为一个完整 transaction
function handleAddComment() {
  const { from, to } = editor.state.selection;
  // 浮层输入文字后：
  editor.chain()
    .focus()
    .setTextSelection({ from, to })
    .setMark("comment", { commentId: c.id })
    .run();
  // ↑ 一次 transaction 中完成选择 + setMark，按一次 Ctrl+Z 可整体撤销
}
```

删除批注同样用 `unsetMark`：

```ts
function removeCommentMark(commentId: string) {
  // 遍历 doc，移除所有 attr.commentId === commentId 的 mark
  const { state, view } = editor;
  const tr = state.tr;
  state.doc.descendants((node, pos) => {
    node.marks.forEach(mark => {
      if (mark.type.name === "comment" && mark.attrs.commentId === commentId) {
        tr.removeMark(pos, pos + node.nodeSize, mark.type);
      }
    });
  });
  view.dispatch(tr);
}
```

**孤儿扫描**应作为「事务结束」后的副作用：

```ts
// 监听 EditorView 的 transactions
const updateListener = EditorView.updateListener.of((v) => {
  if (v.docChanged) {
    nextTick(() => sweepOrphans());
  }
});
```

## 7. 持久化与版本

### 7.1 数据库

**无需迁移**。批注是 ProseMirror JSON 内部字段，SQLite 不感知其结构。

- `documents.content`（草稿 JSON）：含 `comments` 字段
- `versions.content`（版本 JSON）：提交时序列化，含 `comments` 字段
- `commit_version` / `save_draft` / `get_version` / `get_draft` 命令**无需改动**

### 7.2 版本快照验证

| 场景 | 行为 |
|---|---|
| 提交版本 v1（带 3 条批注） | v1.content 含 3 条 comments |
| 删除第 2 条批注 → 提交 v2 | v2.content 含 2 条 comments；v1 仍含 3 条 |
| 回滚到 v1 | `parseContent(v1.content)` 恢复 3 条批注 + mark |
| 删除整段带批注的文字（不提交） | 草稿 mark 没了 → `sweepOrphans()` 把对应 comment 标 `orphan: true` |
| 删除整段后提交 v2 | v2.content 含 2 条 live + 1 条 orphan |
| 在 v1 视图删除批注 | 仅视图层 mark 变化，不持久化；切回最新草稿/v2 又出现 |

### 7.3 草稿保存

沿用现有 `scheduleDraftSave`（500ms 防抖），`comments` 数组在调用 `serializeContent` 时一起写入。

## 9. 备份导出/导入

### 9.1 数据结构

现有 `restore_backup` / 导出数据是分类别的：


**批注不需要新类别**——它嵌在 `documents` 和 `versions` 的 `content` 字段里。导出文档时自动包含。

### 9.2 API 设置面板的备份模块

### 9.3 兼容性

- **导出 v2 → 导入 v1（理论场景）**：导入时 `parseContent` 容错 `comments === undefined` → 不会报错，但批注会消失。**在备份元数据中记录 `minReaderVersion: 2.0.0`**，导入时若读者版本低于此值则给出警告：「此备份包含批注数据，您的版本不支持，将被忽略」
- **导出 v1 → 导入 v2**：`parseContent` 默认 `comments = []`，无副作用
- **跨设备**：依赖 ProseMirror doc 结构完全一致，v1 阶段在文档头部加 `docSchemaVersion: 1`，导入时校验

## 10. 边界与异常处理

| 场景 | 处理 |
|---|---|
| 选区为空 | 工具栏按钮 disabled + 提示「请先选中要批注的文字」 |
| 跨段选区 | 提示「批注暂不支持跨段，请选择同一段内的文字」 |
| 批注文本 > 500 字 | 浮层 textarea `maxlength=500`，超出截断 |
| 同一选区重复插入批注 | 在该选区上叠加多条 mark（不同 `commentId`），角标都显示 |
| mark 跨多个 inline 节点（如 `bold` 内） | ProseMirror Mark 天然支持 `spanning: true` |
| 撤销/重做 | 通过 ProseMirror transaction 保证 |
| 删除带批注的整段 | mark 消失 → `sweepOrphans()` 把 comment 标 orphan，文末标灰显示 |
| 用户手动编辑孤儿批注 | 文末面板可改 text、不可跳转 anchor；可手动删除 |
| 提交版本时 hover 浮层未关闭 | 不影响提交；浮层在切换视图时统一关闭 |
| 导入老版本备份 | `parseContent` 容错，不报错 |
| 导入跨 schema 文档 | `docSchemaVersion` 不匹配时警告用户 |

## 11. 性能

- 批注数量：公文场景通常 < 50 条/文档，**无忧**
- 角标渲染：Decoration 是 O(n)（n=带 mark 的节点数），50 条 < 1ms
- 孤儿扫描：`sweepOrphans` 在 `docChanged` 后 nextTick 异步执行，不阻塞输入
- 文末列表：纯 Vue 渲染，50 条 < 16ms
- 备份大小：批注文本一般 < 1KB/条，100 条 + 100 版本 ≈ < 200KB 增量

**无需特殊优化**。

## 15. 关键设计决策（已与需求方确认）

| 决策 | 选择 | 理由 |
|---|---|---|
| 批注存储位置 | doc 内部 JSON（`comments` 字段） | 草稿/版本/回滚/备份自动同步，零额外逻辑 |
| 单段/跨段 | v1 单段内，跨段 UI 引导 | schema 简单、稳定性高 |
| 删除带批注段落 | 保留为孤儿 + 文末标灰 | 公文场景有保留价值 |
| Word 原生批注 | 不做，转文末列表 + 角标 | 工程量 1/5、价值 80% |
| 多用户/协作 | 不做 | 需求明确为单用户 |
| Mark 跨 inline 节点 | 支持（`spanning: true`） | 覆盖加粗/斜体中的批注 |
| 角标实现 | Decoration（视图层），不写回 JSON | 避免污染文档结构、删除/复制无副作用 |
| 备份勾选 | 不新增类别，仅说明 | 批注随文档/版本自动导出 |

## 16. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 跨段 mark 边界 bug | 中 | 中 | v1 限制单段，UI 引导 |
| ProseMirror schema 升级导致旧文档 mark 失效 | 低 | 高 | 文档头部 `docSchemaVersion` + 导入校验 |
| 备份体积膨胀 | 低 | 低 | 文末列表只渲染当前文档批注，备份是单文档粒度 |
| Hover 浮层定位抖动 | 中 | 低 | 监听 view.dom scroll 事件重算 |
| Undo/Redo 行为不符合预期 | 中 | 中 | 充分自测 + 必要时合并事务为单步 |
| 大量批注 (>200) 性能下降 | 极低 | 低 | 当前架构下无虞；如发生可加虚拟列表 |
