## 用户需求

技能模块中删除自定义技能时，先弹出确认提示，确认后才执行删除，防止误删。

## 产品概述

在技能面板（SkillPanel）中，针对"自定义技能"（非内置，即 `!skill.is_builtin`）的删除按钮增加二次确认弹窗。点击删除按钮不再直接执行删除，而是先弹出一个危险操作确认框，用户确认后才真正调用后端删除并刷新列表。

## 核心功能

- 自定义技能删除按钮点击后，先弹出确认对话框（标题/提示/危险样式/确定(删除)与取消按钮）。
- 用户点击"取消"或按 ESC 关闭弹窗，不执行任何删除操作。
- 用户点击"删除"确认后，才执行原有删除逻辑（调用 `delete_skill` 并清理本地状态）。
- 内置技能（`is_builtin`）不存在删除按钮，行为不变。

## 技术栈

- 前端框架：Vue 3 (`<script setup>` + TypeScript)
- 全局确认弹窗：`src/components/ConfirmDialog.vue`（已在 `App.vue` 中通过 `registerConfirmDialog` 全局注册）
- 确认能力组合式：`src/composables/useConfirm.ts`，返回 `confirm(opts: ConfirmOptions): Promise<boolean>`

## 实现方案

复用项目已有的全局确认弹窗体系，而非自行实现弹窗或仅使用浏览器原生 `window.confirm`。这与 `VersionList.vue`、`MaterialPanel.vue` 等组件中删除确认的做法保持一致，遵循既有约定（DRY / SoC）。

**关键决策**：

- 在 `SkillPanel.vue` 中引入 `useConfirm`，用 `const { confirm } = useConfirm()` 获取确认函数，零额外 UI 成本即可接入全局弹窗。
- 将 `handleDelete(skill)` 改为 `async`，在调用 `invoke("delete_skill")` 之前先 `await confirm({...})`；若返回 `false` 直接 `return`，不做任何状态变更，确保无误删。
- 确认框参数风格对齐项目现有删除确认：`kind: "danger"`、`okLabel: "删除"`、`title: "删除技能"`、消息中包含技能名称以明确操作对象。

**性能与可靠性**：仅在用户点击删除时触发一次异步确认，无额外渲染开销；确认失败（取消/ESC）不产生任何副作用，错误捕获逻辑保持原有 `catch` 处理。

## 实现要点

- 仅在 `SkillPanel.vue` 单文件内修改，不新增任何组件或文件。
- `handleDelete` 需先 `await confirm(...)`，确认为 `true` 才执行后续 `invoke` 与本地状态清理（包括 `resultMap`、`expandedMap`、`skillKbSelection` 的清理）。
- 文案保持与项目其它删除确认一致的中文风格，消息示例：「确定要删除自定义技能「{name}」吗？此操作不可撤销。」

## 架构设计

保持现有组件结构不变。数据流：点击删除按钮 → `handleDelete(skill)` → `await confirm()` 弹窗 → 确认返回 `true` → `invoke("delete_skill")` → 更新 `skills` 及关联本地状态映射。
